- 2026-10-07: Ran mini-sglang three ways (an offline script, the chat shell, and the server with curl) and worked through how it fits together. A server runs three processes: the API server, a tokenizer process, and the scheduler, the only one that uses the GPU. Tokenizing has its own process so that the scheduler can keep feeding the GPU: on my laptop, tokenizing an 8,000-token prompt takes 28 ms, about 3.5 decode steps. There is only one detokenizer because it keeps state per request: a character split across two tokens can only be sent once both have arrived. For the KV cache, I followed one token from its slot in the page table to its bytes in GPU memory: one `torch.empty` call, 2 KiB per token per layer, written by a small CUDA kernel and read by FlashInfer through a list of slot numbers, with no copy. nano-vllm uses the same memory layout with 256-token blocks, because flash-attn's paged kernel requires blocks of a multiple of 256. I also walked the radix tree with real tokens. Q&A in Chinese: [processes](../../notes/mini-sglang/QA-processes.md), [KV cache and radix tree](../../notes/mini-sglang/QA-kv-cache.md).

- 2026-10-08: Learned mini-sglang's two signature features, the radix cache and overlap scheduling, and how they interact. The radix cache keeps a finished request's KV in the tree, locks a prefix while a request uses it, and evicts the least recently used leaves, a whole node at a time, only when memory runs out. Overlap scheduling launches the next step before it processes the last one; the sampled tokens are handed over on the GPU, so the CPU work hides behind the GPU. The cost is that the scheduler's information is one step late: a prompt computed in one step is inserted into the tree only after the next step has been scheduled, so a request admitted in that step misses the shared prefix and computes it again. When its duplicate copy is then freed, its page table still points at the freed slots, which is the problem PRs #142 and #154 fix. It came in with the February change that started caching unfinished requests; SGLang has written the cached indices back at this point since at least v0.3.0. This is from the code and my scheduler simulation; a minimal reproduction is next. I also changed the simulation to print each step twice, when it is launched and after its results are processed, because a single print per step was easy to misread. Q&A in Chinese: [overlap scheduling](../../notes/mini-sglang/QA-overlap.md), and a new section in [KV cache and radix tree](../../notes/mini-sglang/QA-kv-cache.md).
