## Learned

**#274**

- Thought the "preempt itself" lines were the bug -> traced them by hand -> preempting itself is right in other cases -> the real problem: nothing can run this step + it will never fit | whether it can come back depends on the total cache size, not on what is free right now
- The "D is still running" example from the discussion -> didn't add up: B already fills the cache, so where do D's blocks come from? -> pushed on it, and that case cannot happen at all | an explanation that sounds right is not necessarily right; count the blocks yourself
- Check placed in `schedule()` -> nothing can run this step, and the output gets lost -> moved it to `postprocess()` -> reuses the normal finish path | where a check lives matters as much as what it checks
